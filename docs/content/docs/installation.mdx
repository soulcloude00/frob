## Global installation (recommended)

Installs the native Rust binary for maximum performance:

```bash
npm install -g frob
frob install  # Download Chrome from Chrome for Testing (first time)
```

This is the fastest option -- commands run through the native Rust CLI directly with sub-millisecond parsing overhead.

npm, pnpm, Yarn, and Bun download only the binary for your platform, from a matching `@frob/cli-*` optional dependency. The global `frob` command runs the native binary directly. Package managers that block install scripts by default, such as npm 12, pnpm, and Bun, link it on the first run instead, so no extra setup is needed. Installing with `--omit=optional` skips the binary; reinstall without that flag.

On macOS versions below 13, `frob install` stops before downloading Chrome for Testing and prints instructions to update macOS or install Chrome manually. Update macOS to version 13 or later through **System Settings > General > Software Update**, or install Chrome from [Google's Chrome download page](https://www.google.com/chrome/). This check applies when you run `frob install`; the package installation commands above remain unchanged. If `sw_vers -productVersion` is unavailable, exits with an error, returns no version, or returns a malformed version, `frob install` reports a detection error and stops before making a network request.

## Quick start (no install)

```bash
npx frob install   # Download Chrome (first time only)
npx frob open example.com
```

## Cargo (Rust)

```bash
cargo install frob
frob install  # Download Chrome (first time)
```

Compiles from source (~2-3 min). Requires Node.js 24+, pnpm 11+, and the Rust toolchain ([rustup.rs](https://rustup.rs)).

```bash
cd frob
pnpm install

pnpm link --global
frob install
```

## Windows browser sessions

Headless Chrome runs on a private Windows desktop. This prevents hidden browser windows from leaving visible rectangles on your desktop, including with affected Chrome 150 builds. It applies to bundled and custom Chrome executables and to windows created later in the session. Automation, screenshots, and GPU rendering continue through CDP.

Use `--headed` to show Chrome on the interactive desktop. Sessions with extensions also use the interactive desktop. Frob owns the Chrome processes it launches: Windows terminates the entire Chrome tree when its daemon exits or is forcibly killed. Browsers attached with `--cdp` or `--auto-connect` remain externally owned.

## Linux dependencies

On Linux, install system dependencies:

```bash
frob install --with-deps
```

This exits nonzero if the package manager cannot install every required browser library.

When run as root, this command calls the detected package manager directly. For non-root users, it uses `sudo`. If you are not root and `sudo` is unavailable, it reports that root privileges or `sudo` are required.

## Updating

Upgrade to the latest version:

```bash
frob upgrade
```

Detects your installation method (npm, Homebrew, or Cargo) and runs the appropriate update command automatically. Displays the version change on success, or informs you if you are already on the latest version.

## Doctor

`doctor` diagnoses your install and auto-cleans stale daemon files. Run it whenever something stops working unexpectedly, or after upgrades:

```bash
frob doctor                     # Full diagnosis
frob doctor --offline --quick   # Local-only, fastest (~<1s)
frob doctor --fix               # Also run destructive repairs
frob doctor --webgpu            # Also run a live WebGPU render probe
frob doctor --json              # Structured output
```

Stale sidecar files are always cleaned. Destructive actions are opt-in via `--fix`:

<table>
<thead>
<tr><th>Check</th><th>What <code>--fix</code> does</th></tr>
</thead>
<tbody>
<tr><td>Chrome missing</td><td>Runs <code>frob install</code></td></tr>
<tr><td>Version-mismatched daemons</td><td>Sends <code>close</code> to each and cleans files</td></tr>
<tr><td>Old state files</td><td>Deletes state files older than <code>FROB_STATE_EXPIRE_DAYS</code> (default 30)</td></tr>

</tbody>
</table>

Exit code is `0` if all checks pass (warnings are fine), `1` if any fail.

## Custom browser

Use a custom browser executable instead of bundled Chromium:

- **Serverless** - Use `@sparticuz/chromium` (~50MB vs ~684MB)
- **System browser** - Use existing Chrome installation
- **Custom builds** - Use modified browser builds

```bash
# Via flag
frob --executable-path /path/to/chromium open example.com

# Via environment variable
FROB_EXECUTABLE_PATH=/path/to/chromium frob open example.com
```

### Serverless example

Use `@sparticuz/chromium` or similar to obtain a Chromium executable path, then pass it via `--executable-path` or `FROB_EXECUTABLE_PATH`.

For example, in an AWS Lambda handler:

```typescript
import chromium from "@sparticuz/chromium";
import { execSync } from "child_process";

export async function handler() {
  const executablePath = await chromium.executablePath();
  const result = execSync(
    `FROB_EXECUTABLE_PATH=${executablePath} frob open https://example.com && frob snapshot -i --json`,
    { encoding: "utf-8" }
  );
  return JSON.parse(result);
}
```

### AGENTS.md / CLAUDE.md

Add to your instructions file:

```markdown
## Browser Automation

Use `frob` for web automation. Run `frob --help` for all commands.

Core workflow:
1. `frob open <url>` - Navigate to page
2. `frob snapshot -i` - Get interactive elements with refs (@e1, @e2)
3. `frob click @e1` / `fill @e2 "text"` - Interact using refs
4. Re-snapshot after page changes
```
