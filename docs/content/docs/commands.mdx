## Core

Unknown commands exit with status 1, including when you request command help.

When the top-level Chrome/CDP `eval` result is a value JSON cannot represent, plain output prints its exact JavaScript token, including `NaN`, `Infinity`, `-Infinity`, `-0`, BigInt literals, and `undefined`. With `--json`, `data.result` stays `null` and sibling `data.unserializable` contains the token. MCP text prints the token, and structured responses expose it at `structuredContent.response.data.unserializable`.

```bash
frob open                    # Launch browser (no nav); stays on about:blank
frob open <url>              # Launch + navigate (aliases: goto, navigate)
frob read [url]              # Fetch agent-readable text, or read rendered active-tab DOM
frob click <sel>             # Click element (--new-tab to open in new tab)
frob dblclick <sel>          # Double-click
frob fill <sel> <text>       # Clear and fill
frob type <sel> <text>       # Type into element
frob press <key>             # Press key (Enter, Tab, Control+a) (alias: key)
frob keyboard type <text>    # Type at current focus (no selector needed)
frob keyboard inserttext <text>  # Insert text without key events
frob keydown <key>           # Hold key down
frob keyup <key>             # Release key
frob hover <sel>             # Hover element
frob focus <sel>             # Focus element
frob select <sel> <val>      # Select dropdown by value or visible label
frob check <sel>             # Check checkbox
frob uncheck <sel>           # Uncheck checkbox
frob scroll <dir> [px]       # Scroll (up/down/left/right, --selector <sel>)
frob scrollintoview <sel>    # Scroll element into view
frob drag <src> <dst>        # Drag and drop
frob upload <sel> <files>    # Upload files
frob screenshot [path]       # Screenshot (--full for full page)
frob screenshot --annotate   # Annotated screenshot with numbered element labels
frob screenshot --if-changed # Recommended: skip unchanged images to save tokens
frob screenshot --threshold 0.01 # Ignore changes affecting at most 1% of pixels
frob screenshot --screenshot-dir ./shots    # Save to custom directory
frob screenshot --screenshot-format jpeg --screenshot-quality 80
frob pdf <path>              # Save page as PDF
frob snapshot                # Accessibility tree with refs
frob eval <js>               # Run JavaScript
frob connect <port|url>      # Connect to browser via CDP
frob stream enable [--port <port>]  # Start runtime WebSocket streaming
frob webmcp list                     # List experimental page tools
frob webmcp invoke <tool> --params @input.json
frob stream status           # Show runtime streaming state and bound port
frob stream disable          # Stop runtime WebSocket streaming
frob close                   # Close browser (aliases: quit, exit)
frob close --all             # Close all active sessions
frob mcp                     # Start an MCP stdio server
frob mcp call <tool> <json>  # Run one MCP tool and print its result
```

For `fill` and `type`, put options before the optional `--` marker. Text after the marker is literal, including values that look like flags. For example, `frob fill "#search" -- --json` fills with `--json`, and `frob --json type "#search" --clear --delay 10 -- --clear` clears the field, then types `--clear`. MCP `frob_fill` and `frob_type` pass typed `text` values literally, so they do not need the marker.

`select` works on a native `<select>` and on a custom ARIA combobox or listbox, such as Radix or Headless UI. On a custom widget it opens the widget, then clicks the `role=option` whose name or value matches. A value with no match is an error that lists the available options, a matched option marked `aria-disabled` is an error instead of a click, and an option already selected in a multi-select listbox is left alone.

Browser responses automatically announce WebMCP tools on first discovery and when the catalog changes. Summaries contain only names, brief descriptions, origins, and frame IDs. Choose a relevant tool, then fetch its full schema with `frob webmcp list <tool> --frame <frame-id> --json` before invoking it. Schemas and annotations are never included proactively. Unchanged catalogs and pages without tools add no context. JSON exposes updates as `data.webmcp`; CLI and MCP text include the same bounded summary. See [WebMCP](/webmcp) for update semantics and security.

Clicks fail before dispatch when another element covers the target's click point. The error names the covering element, for example `covered by <div#consent-banner>`. Dismiss or interact with that element, take a fresh snapshot, then retry the original action. Click and dblclick fail, instead of reporting success, when the element is hidden, disabled, or outside the viewport. `click --new-tab` opens the link's URL directly, so these checks do not apply to it.

Headless Chromium screenshots hide native scrollbars for consistent image output. Pass `--hide-scrollbars false` when launching to keep native scrollbars visible.

## Get info

```bash
frob get text <sel>          # Get text content
frob get html <sel>          # Get innerHTML
frob get value <sel>         # Get input value
frob get attr <sel> <attr>   # Get attribute
frob get title               # Get page title
frob get url                 # Get current URL
frob get cdp-url             # Get CDP WebSocket URL
frob get count <sel>         # Count matching elements
frob get box <sel>           # Get bounding box
frob get styles <sel>        # Get computed styles
```

`get cdp-url` reports the CDP WebSocket URL of a browser that is already running. It requires a running browser and never launches one. A batch containing only `get cdp-url` commands also skips browser launch. A mixed batch can launch a browser for its other commands.

## Read agent-friendly text

```bash
frob read
frob read https://example.com/article
frob read https://example.com/article --filter overview
frob read https://example.com/article --outline
frob read https://docs.example.com --llms index --filter auth
frob read https://docs.example.com --llms full --filter auth
frob read example.com/article --require-md
frob read https://example.com/article --json
```

`read` fetches a URL without launching Chrome. Omit the URL to read the rendered DOM of the active tab in the current browser session, including browser auth state and client-side updates. Explicit URL reads send `Accept: text/markdown` by default, try the same URL with `.md` appended when the first response is not markdown, walk ancestor paths toward `/` to find the nearest `llms.txt` for a matching docs link, print markdown or plain text when available, and fall back to readable text extracted from HTML. `--llms` and `--require-md` with no URL use the active tab URL because they depend on HTTP resources. `read` does not read `llms-full.txt` unless you ask for it.

Options: `--raw` prints the response body without HTML extraction, `--require-md` fails unless the server returns `Content-Type: text/markdown`, `--outline` prints a compact heading outline for one page, `--llms index` prints a compact nearest-ancestor `llms.txt` link list, `--llms full` reads the nearest-ancestor `llms-full.txt`, `--filter <text>` narrows page sections, llms links/sections, or outline headings, and `--timeout <ms>` changes the request timeout. Global safeguards such as `--allowed-domains`, `--content-boundaries`, and `--max-output` also apply to read fetches and output.

## Find elements

Semantic locators with actions (`click`, `fill`, `check`, `hover`, `text`):

```bash
frob find role <role> <action> [value]
frob find text <text> <action> [value]
frob find label <label> <action> [value]
frob find placeholder <ph> <action> [value]
frob find alt <text> <action> [value]
frob find title <text> <action> [value]
frob find testid <id> <action> [value]
frob find first <sel> <action> [value]
frob find last <sel> <action> [value]
frob find nth <n> <sel> <action> [value]
```

Options:

- `--name <name>`: filter role by accessible name
- `--exact`: exact, case-sensitive match. For `role` it applies to the accessible name, whose default is a case-insensitive substring.

Examples:

```bash
frob find role button click --name "Submit"
frob find role heading text --name "Skills"     # implicit roles work: <h2>=heading, <ul>=list, top-level <header>=banner
frob find label "Email" fill "test@test.com"
frob find alt "Logo" click
frob find first ".item" click
frob find last ".item" text
frob find nth 2 ".card" hover
```

## Wait

```bash
frob wait <selector>         # Wait for element
frob wait <ms>               # Wait for time
frob wait --text "Welcome"   # Wait for text (substring match)
frob wait --url "**/dash"    # Wait for URL pattern
frob wait --load domcontentloaded # Wait for DOMContentLoaded
frob wait --load load        # Wait for the load event
frob wait --load networkidle # Use only for pages known to become quiet
frob wait --fn "condition"   # Wait for JS condition
frob wait --download [path]  # Wait for download
frob wait --fn "!document.body.innerText.includes('Loading...')"  # Wait for text to disappear
frob wait "#spinner" --state hidden           # Wait for element to disappear
```

For selector waits, `--state` accepts `visible`, `hidden`, `attached`, or `detached` and cannot be combined with URL, load, function, text, download, or millisecond wait modes. The global auth-state `--state <path>` remains available before `wait`, as it does before other commands.

After a page change, prefer a selector, text, URL, or JavaScript condition that represents the state you need. Use `networkidle` only when the page is known to become quiet, because SSE, WebSockets, polling, and long-polling can keep it from resolving.

A load-state wait runs for its whole timeout budget, taken from `--timeout` or `FROB_DEFAULT_TIMEOUT`, and returns an error when it expires.

## Downloads

```bash
frob download <sel> <path>   # Click element to trigger download
frob wait --download [path]  # Wait for any download to complete
```

`wait --download` returns the oldest download not yet claimed by an earlier wait, including one that finished before the command ran, so it can follow the command that triggered it. With `[path]`, the file is moved there; without it, the output is where the browser saved it. Saving to a local path only applies to a browser frob launched: over `--cdp`, `--auto-connect`, or a provider, the saved file is named by the remote endpoint, so `download` and `wait --download [path]` are rejected.

Use `--download-path <dir>` (or `FROB_DOWNLOAD_PATH` env) to set a default download directory. Without it, downloads go to a temporary directory that is deleted when the browser closes.

See [Files & Clipboard](/files) for upload, download, local file, screenshot, PDF, and clipboard workflows.

## Mouse

```bash
frob mouse move <x> <y>      # Move mouse instantly
frob mouse move 600 400 --duration 250 --steps 24
frob mouse move 600 400 --human --seed 42
frob mouse down [button]     # Press button
frob mouse up [button]       # Release button
frob mouse wheel <dy> [dx]   # Scroll wheel
```

The wheel scrolls at the current tracked pointer, which starts at `0,0`. Failed wheel dispatches leave the tracked pointer unchanged.

Mouse coordinates and wheel deltas accept finite decimal values; invalid supplied values are rejected. For `mouse wheel`, omitted `dy` and `dx` default to `100` and `0`, respectively, and explicit `0` values are preserved.

To scroll elsewhere, move the pointer first:

```bash
frob mouse move 600 400
frob mouse wheel 100
```

Use `--human` with `click`, `drag`, or `mouse move` for curved, eased movement from the current cursor position. For `mouse move`, `--duration` sets the target total milliseconds including browser response time, `--steps` sets the number of events, and `--seed` makes the path reproducible. A slow browser can still extend the requested duration.

## Cookies & storage

```bash
frob cookies                 # Get all cookies
frob cookies set <name> <val> # Set cookie
frob cookies clear           # Clear cookies

frob storage local           # Get all localStorage
frob storage local <key>     # Get specific key
frob storage local set <k> <v>  # Set value
frob storage local clear     # Clear all

frob storage session         # Same for sessionStorage
```

Reads accept at most one key, sets require one key and one value, and clears take no operands. A bare key is shorthand for a one-key read.

Cookie operations are `get` (the default), `set`, and `clear`; unknown operations return an error. Cookie attributes use kebab-case flags such as `--http-only` and `--same-site`. The legacy `--httpOnly` and `--sameSite` spellings remain accepted. When setting one cookie, unknown flags and extra arguments return an error.

```bash
frob cookies set session_id abc123 --http-only --same-site Strict
```

## Tabs & frames

```bash
frob tab                              # List tabs (each row shows tabId and label)
frob tab new [url]                    # New tab
frob tab new --label docs [url]       # New tab with a user-assigned label
frob tab <t<N>|label>                 # Switch to a tab by id or label
frob tab close [t<N>|label]           # Close a tab (defaults to active)
frob window new                       # Open new browser window
frob frame <sel>                      # Switch to iframe by CSS selector
frob frame @e3                        # Switch to iframe by element ref
frob frame main                       # Back to main frame
```

### Stable tab ids and labels

Tab ids are stable strings of the form `t1`, `t2`, `t3`. They're never reused within a session, so `t2` keeps pointing at the same tab even as other tabs are opened or closed. The `t` prefix mirrors the `@e1` element-ref convention and is not interchangeable with positional integers — `frob tab 2` errors with a teaching message; use `t2`.

You can also assign a memorable label (`docs`, `app`, `admin`) at tab-creation time and use it anywhere an id is accepted:

```bash
frob tab new --label docs https://docs.example.com
frob tab docs          # switch to the docs tab
frob snapshot          # populate refs for docs
frob click @e3         # click uses docs's refs
frob tab close docs    # close by label
```

Labels are never auto-generated and never rewritten on navigation — an agent that names a tab `docs` keeps that name until the tab is closed. Labels are unique within a session; creating a second tab with an existing label errors.

A label starts with a letter and contains only letters, digits, `-`, or `_`, and cannot use the reserved `t<N>` or `T<N>` tab-id form. Rejected labels preserve the current tab's refs and selected frame.

Tabs opened through `tab new` or `click --new-tab` inherit the session's setup before their first document loads: user agent, `set headers`, `set credentials`, origin-scoped `--headers`, init scripts, `route` rules, and emulation overrides (color scheme, timezone, locale, geolocation, offline). Turning offline mode off or setting headers to `{}` restores the default setup for future tabs.

`tab list --json` also reports each tab's CDP `targetId`, and target ids are accepted anywhere a tab ref is accepted (`tab <targetId>`, `tab close <targetId>`). Unlike `t<N>` ids, which are per-daemon counters, target ids stay stable across daemon restarts. Each session is bound to its active tab by target id and returns to it after a daemon restart; with `--pin-tab` the binding is strict and a closed bound tab produces a `tab_gone` error instead of a silent fallback. JSON errors include <code>code: "tab_gone"</code>, <code>data.targetId</code>, and optional sanitized <code>data.lastUrl</code>. Batch output carries the recovery object under <code>result</code>. See [CDP Mode](/cdp-mode) for the multi-session workflow.

Refs (`@e1`, etc.) are scoped to the tab that was active when the snapshot ran, so switch tabs first, then snapshot and interact:

```bash
frob tab docs          # switch first
frob snapshot          # refs for docs
frob click @e3         # uses docs's refs
```

### Discarded tab revival

Browsers discard background tabs to save memory, leaving a tab with no renderer to drive. Switching to a discarded tab reactivates it, which reloads the page and resets its unsaved state; the switch result adds `"revived": true` so the reload is visible rather than silent. A tab whose page is paused by a JavaScript dialog is alive rather than discarded: the switch leaves it untouched and adds `"dialogBlocked": true`. Resolve the dialog with `dialog accept` or `dialog dismiss` and the tab keeps its state. Closing the active tab onto a discarded successor revives it the same way and reports `"activeTabRevived": true`.

### Snapshot deltas

```bash
frob snapshot --delta
frob snapshot --delta --full
```

`snapshot --delta` returns `full`, `unchanged`, or incremental updates per tab and option set. URL changes or large deltas return full state; `--full` resets the baseline. Apply a delta’s `changes` to ref metadata and `treeChange` to the previous tree: split on newlines, replace `deleteCount` lines at zero-based `startLine` with `lines`, then rejoin. Apply both to `baseRevision` before advancing to `revision`.

### Observe after an action

```bash
frob --observe click @e3
frob --observe open https://example.com
FROB_OBSERVE=1 frob fill @e5 "hello"
```

With `--observe`, a page-changing action (`open`, `back`, `forward`, `reload`, `click`, `dblclick`, `fill`, `type`, `press`, `keyboard`, `hover`, `focus`, `select`, `check`, `uncheck`, `scroll`, `drag`, `upload`, and similar) waits for the page to settle and reports what it did in the same response, so you do not need another snapshot. The page counts as settled once its DOM has not changed for 100 ms and no request or short timer the action started is still pending, up to 2 seconds.

The `observe` block in the response holds the interactive snapshot lines that appeared (`+`) or went (`-`), with fresh refs, as `changes`; `changed: false` when nothing changed; `navigated` and the new page's interactive `snapshot` when the action left the page; and `console` warnings and errors and `pageErrors` the action caused. `FROB_OBSERVE=1` turns it on for every action the daemon runs, and `--no-observe` turns it off for one command. In MCP, set `observe: true` on the action tool.

### Merged and collapsed snapshots

A list item, table cell, or heading that only wraps one element whose name contains its own is printed on that element's line, and both refs work:

```
- listitem [level=1, ref=e3] > link "Twin bed $80 Castro Valley" [ref=e4]
```

Set `FROB_SNAPSHOT_MERGE=0` to print them on separate lines.

```bash
frob snapshot -i --collapse
frob snapshot -i --collapse 80
frob snapshot -i --collapse -s @e406
```

`--collapse [n]` keeps a snapshot under `n` lines (default 150) by folding its biggest sections, largest first, into one line that keeps the section's ref and counts the refs inside, such as `- region "References" [ref=e406] (collapsed: 829 refs)`. The refs inside stay valid. Scope a snapshot to a folded section's ref with `-s` to open it, keeping `--collapse` to drill down further. A page within the budget prints unchanged, and flat pages with no sections print in full. In MCP, set `collapse` on `frob_snapshot` to the line budget.

### Iframe support

Iframes are detected automatically during snapshots. `Iframe` nodes are resolved and their content is inlined beneath the iframe element in the snapshot output. Refs assigned to elements inside iframes carry frame context, so `click`, `fill`, and other interactions work without manually switching frames.

```bash
frob snapshot -i
# - Iframe "payment-frame" [ref=e3]
#   - textbox "Card number" [ref=e4]
#   - button "Pay" [ref=e5]

# Interact directly using refs — no frame switch needed
frob fill @e4 "4111111111111111"
frob click @e5

# Or switch frame context for scoped snapshots
frob frame @e3
frob snapshot -i             # Only elements inside that iframe
frob frame main              # Return to main frame
```

The `frame` command accepts element refs (`@e3`), CSS selectors (`"#my-iframe"`), or frame name/URL.

## Dialogs


By default, `alert` and `beforeunload` dialogs are automatically accepted so they never block the agent. `confirm` and `prompt` dialogs still require explicit handling. Use `--no-auto-dialog` (or `FROB_NO_AUTO_DIALOG=1`) to disable automatic handling.

## Auth vault

```bash
frob auth save <name> [opts]    # Save auth profile
frob auth login <name>          # Login using saved credentials
frob auth login <name> --no-navigate
                                          # Use active page after origin validation
frob auth login <name> --credential-provider <plugin> [--item <ref>] [--url <url>]
                                          # Resolve credentials from plugin
frob auth login <name> --username-selector <s> --password-selector <s> [--submit-selector <s>]
                                          # Override selectors for one login
frob auth list                  # List saved profiles (names and URLs only)
frob auth show <name>           # Show profile metadata (no passwords)
frob auth delete <name>         # Delete a saved profile
frob plugin add <ref>           # Add a plugin from npm or GitHub
frob plugin list                # List configured plugins
frob plugin show <name>         # Show one configured plugin
frob plugin run <name> <type> --payload <json>
                                          # Run an arbitrary plugin request
```

Save options:

- `--url <url>`: login page URL (required)
- `--username <user>`: username (required)
- `--password <pass>`: password (required unless `--password-stdin`)
- `--password-stdin`: read password from stdin (recommended to avoid shell history exposure)
- `--username-selector <sel>`: custom CSS selector for username field
- `--password-selector <sel>`: custom CSS selector for password field
- `--submit-selector <sel>`: custom CSS selector for submit button

`auth login` filters matching controls by their layout size, computed visibility and opacity, and disabled/readonly state, including custom CSS selectors. If a selected credential field is replaced or redirects focus before entry, the command fails without submitting.

`auth login` navigates with `load` and then waits for the username/password/submit selectors to appear before interacting. This improves reliability on SPA login pages where fields render after initial page load.

Use `--no-navigate` after an in-page click, challenge clearance, consent dismissal, or other stateful setup that must survive credential entry:

```bash
frob open https://example.com/
frob click "a[href='/login']"
frob auth login work --no-navigate
```

The flag suppresses only the initial auth-login navigation. It requires an existing active top-level HTTP(S) page and compares that page with the effective credential URL by scheme, host, and effective port. Paths, queries, and fragments may differ. Waiting, filling, clicking submit, and any submit-triggered navigation are unchanged. A command-level `--url` overrides profile or provider URL metadata and acts as the expected-origin constraint rather than a navigation destination.

Plugin login options:

- `--credential-provider <plugin>`: resolve credentials from a configured plugin
- `--item <ref>`: provider-specific vault item reference
- `--url <url>`: login URL override
- `--no-navigate`: use the active top-level page after validating it against the effective credential origin
- `--username-selector <sel>`: selector override for this login
- `--password-selector <sel>`: selector override for this login
- `--submit-selector <sel>`: selector override for this login

Credential provider plugins run out-of-process over the `frob.plugin.v1` stdio JSON protocol. They return credentials to the daemon for a single login and frob does not save those credentials locally.

Other plugin capabilities use the same protocol:

- `browser.provider`: use the plugin with `--provider <name>` to return a CDP WebSocket URL
- `launch.mutate`: append local launch args, extensions, or init scripts before Chrome starts
- `command.run`: run arbitrary namespaced requests through `frob plugin run`

`plugin run` is for `command.run` and custom capabilities. Core capabilities and protocol request types use their dedicated command paths.

```bash
echo "pass" | frob auth save github --url https://github.com/login --username user --password-stdin
frob auth login github
frob plugin add frob-plugin-vault --name vault
frob auth login my-app --credential-provider vault --item "My App"
frob auth login my-app --credential-provider vault --item "My App" --no-navigate --url https://identity.example.com/login
```

## Confirmation

When `--confirm-actions` is set, certain action categories return a `confirmation_required` response instead of executing immediately. Use `confirm` or `deny` to approve or reject the action.

```bash
frob confirm <confirmation-id>  # Approve a pending action
frob deny <confirmation-id>     # Deny a pending action
```

Pending confirmations auto-deny after 60 seconds.

```bash
frob --confirm-actions eval,download eval "document.title"
# Returns confirmation_required with ID
frob confirm c_8f3a1234
```

## Dashboard

```bash
frob dashboard [start]       # Start the dashboard server (default port: 4848)
frob dashboard start --port <n>  # Start on a specific port
frob dashboard start --allowed-origins <origins> # Allow exact HTTPS reverse-proxied browser origins
frob dashboard stop          # Stop the dashboard server
```

Loopback dashboard origins are accepted by default without an access token. For a reverse-proxied or forwarded URL, pass its exact browser origin with `--allowed-origins` or set `FROB_DASHBOARD_ALLOWED_ORIGINS`. Every configured origin must be a valid exact HTTPS origin. Ports must be integers from 1 to 65535. Unknown options, missing values, invalid ports, and malformed origins fail without starting the server. The command prints private tokenized access URLs only for external origins; open the matching URL once to establish the browser session and do not share it. Open the normal `http://localhost:<port>` URL for local access. The browser stays on the dashboard origin; per-session tabs, status, and stream traffic are proxied internally, so session ports do not need to be exposed. Stop the running dashboard before changing the port or allowed origins.

## Chat

Use natural language to control the browser via AI. The `chat` command translates instructions into frob commands, executes them, and streams the AI response. Requires `AI_GATEWAY_API_KEY` to be set.

```bash
frob chat "open google.com and search for cats"     # Single-shot instruction
frob chat                                           # Interactive REPL (type quit to exit)

frob -q chat "summarize this page"                  # Quiet: text only, no tool calls shown
frob -v chat "fill in the login form"               # Verbose: show commands and their output
frob --model openai/gpt-4o chat "take a screenshot" # Override the default AI model
frob --json chat "open example.com"                 # Structured JSON output
```


## Pre-navigation setup

Some flows need routes, cookies, or init scripts configured *before* the first navigation (SSR debug, auth on protected origins, etc.). `open` without a URL launches the browser but stays on `about:blank`, leaving room to stage state. `batch` makes it one CLI invocation:

```bash
frob batch \
  "open" \
  "network route * --abort --resource-type script" \
  "cookies set --curl cookies.curl --domain localhost" \
  "navigate http://localhost:3000/target"
```

## React / Web Vitals

React commands require `--enable react-devtools` at launch (installs the React DevTools hook before any page JS runs). `vitals` and `pushstate` work on any site.

```bash
frob open --enable react-devtools <url>   # Launch with React hook installed
frob react tree                           # Full component tree
frob react inspect <fiberId>              # Inspect one component
frob react renders start                  # Begin fiber render recording
frob react renders stop [--json]          # Stop + print profile

                                                         # --only-dynamic hides the "static" list

```

`react tree` prints the component tree when one is available. If the response contains only a header, no tree was collected. Confirm the page uses React and that a React root has mounted.

Works on any React app (Next.js, Remix, Vite+React, CRA, TanStack Start, React Native Web, etc.). `vitals` and `pushstate` are framework-agnostic.

## Accessibility audits

Run an embedded axe-core audit against the current page or navigate to a URL first. The vendored engine works without a CDN request and runs under strict page CSP. It runs private partial audits across the page's frame tree and merges serialized results without page messaging, so page-provided `window.axe` values remain intact and iframe violations retain their frame selector paths. Accessibility audits require a CDP browser and are not available with Safari or iOS WebDriver sessions.

```bash
frob a11y                                 # Audit the current page
frob a11y https://example.com             # Navigate, then audit
frob a11y --tags wcag2a,wcag2aa           # Filter by axe rule tags
frob a11y --selector "#main"              # Scope to a subtree
frob a11y https://example.com --json      # Structured results
```

The default output lists violations and incomplete checks with impact, rule ID, fix guidance, and failing-node paths. JSON output preserves axe's `target` selector path arrays, including nested arrays for shadow DOM boundaries and multiple entries for frame boundaries.

## Batch execution

Execute multiple commands in a single invocation. Commands can be passed as quoted arguments or piped as JSON via stdin.

```bash
# Argument mode: each quoted argument is a full command
frob batch "open https://example.com" "snapshot -i" "screenshot"

# With --bail to stop on first error
frob batch --bail "open https://example.com" "click @e1" "screenshot"

# Stdin mode: pipe commands as JSON
echo '[
  ["open", "https://example.com"],
  ["snapshot", "-i"],
  ["click", "@e1"],
  ["screenshot", "result.png"]
]' | frob batch --json

echo '[["fill", "#password", "secret"]]' | frob batch --json --omit-command
```

<table>
  <thead>
    <tr><th>Option</th><th>Description</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--bail</code></td><td>Stop on first error (default: continue all commands)</td></tr>
    <tr><td><code>--json</code></td><td>Output results as a JSON array</td></tr>
    <tr><td><code>--omit-command</code></td><td>With <code>--json</code>, replace each <code>command</code> array with a stable zero-based <code>index</code> field</td></tr>
  </tbody>
</table>

Put global flags such as `--init-script` and `--enable` on the outer batch invocation. Keep command-specific options and literal command arguments inside each item.

```bash
frob --enable react-devtools batch "open" "navigate data:text/html,<h1>hi</h1>"
```

With `--json --omit-command`, rows use a stable zero-based `index` field on success, failure, or `--bail`; default JSON output keeps the `command` field. This only removes command arrays and does not make output safe for secrets. Errors and response data are unchanged: `type` echoes typed text, and `get value`/`eval` may return input values. The MCP `frob_batch` tool accepts `omitCommand: true`.

## MCP server

```bash
frob mcp
frob mcp --tools all
frob mcp --tools core,network,react
frob mcp call frob_open '{"url":"https://example.com"}'
frob mcp --config /path/to/trusted-config.json
frob mcp call frob_open '{"url":"https://example.com"}' --config /path/to/trusted-config.json
echo '{"selector":"@e2"}' | frob mcp call frob_click -
```

Starts a Model Context Protocol server over stdio. MCP clients launch this command as a subprocess and exchange newline-delimited JSON-RPC on stdin and stdout. The server defaults to MCP protocol 2025-11-25 and accepts older supported client protocol versions during initialization. A tool call with an argument its schema does not declare fails with an invalid-params error that names the unknown keys and lists the tool's own arguments.

`mcp call` runs one MCP tool without a stdio session and prints its `tools/call` result as JSON, with the frob version in `_meta.frobVersion`. Pass the tool arguments as a JSON object, or `-` to read them from stdin. Every tool is available unless `--tools` limits the call to profiles. The exit code is 0 on success, 1 when the tool reports an error, and 2 for an unknown tool or invalid arguments. Use it from runtimes that cannot keep a stdio session open between tool calls, such as serverless agents. Access settings such as `FROB_ALLOWED_DOMAINS` come from the environment, as with the server.

For tool calls that run the CLI, `structuredContent.response` contains parsed CLI JSON. `stdout` is included only when the output cannot be parsed as JSON; `exitCode` and `stderr` are always included.

In a Vercel Sandbox, `startFrobMcp` runs the server over the sandbox command's stdin. See [Next.js + Vercel](/next#mcp-server-over-stdin).

The default tools profile is `core`, which keeps MCP context small for everyday browser automation. Use `--tools all` for the full typed CLI parity surface, or combine profiles with commas, such as `--tools core,network,react`.

Profiles:

- `core` - Default. Navigation, snapshots, interaction, waits, reads, screenshots, JavaScript eval, close, tab basics, and profile discovery
- `network` - Network routes, request inspection, HAR, headers, credentials, offline
- `state` - Cookies, storage, auth, saved state, sessions, profiles, skills
- `debug` - Console/errors, tracing, profiling, recording, accessibility audits, clipboard, plugins, doctor, dashboard, install, upgrade, chat, diff, batch, confirm/deny
- `tabs` - Back/forward/reload, tabs, windows, frames, dialogs
- `react` - React tree/inspect/renders/suspense, vitals, pushstate
- `mobile` - Viewport/device/geolocation/media, touch, swipe, mouse, keyboard
- `all` - Every MCP tool, including the full typed CLI parity surface

Example MCP client config:

```json
{
  "mcpServers": {
    "frob": {
      "command": "frob",
      "args": ["mcp"]
    }
  }
}
```

With `--tools all`, the server exposes typed tools across the CLI command surface, including navigation, snapshots, input, waits, screenshots/PDF, get/is/find, mouse, network, storage, cookies, tabs, windows, frames, dialogs, tracing, recording, accessibility audits, clipboard, auth, state, iOS, diff, React, vitals, sessions, skills, plugins, doctor, dashboard, install, upgrade, chat, eval, and close.

Common tools include:

- `frob_tools_profiles`
- `frob_open`
- `frob_snapshot`
- `frob_click`
- `frob_fill`
- `frob_type`
- `frob_press`
- `frob_wait_for_selector`
- `frob_screenshot`
- `frob_get_url`
- `frob_eval`
- `frob_close`

Each tool has typed fields such as `url`, `selector`, `text`, and `key`, so MCP clients show meaningful approval prompts instead of raw command arrays. Tool discovery is paginated and includes read-only/open-world annotations so modern MCP clients can load the large typed surface incrementally.

Every tool also accepts the shared arguments `session`, `restore`, `allowedDomains`, `extraArgs`, `timeoutMs`, `namespace`, `restoreSave`, `restoreCheckUrl`, `restoreCheckText`, `restoreCheckFn`, `caCert`, `useSystemCa`, `clearCaCert`, `idleTimeout`, and `relaunch`. A tool's schema lists only the ones that usually matter for it: `session` on every tool, `restore` and `relaunch` on `open` and `tab_new`, `allowedDomains` and `extraArgs` on `open`, `tab_new`, and `read`, and `timeoutMs` on tools that navigate, wait, or run scripts. The server's `initialize` instructions describe all of them. `allowedDomains` maps to `--allowed-domains`, activates the same WebRTC containment and launch-mode restrictions, and is rejected when the server already sets allowed domains. `idleTimeout` maps to `--idle-timeout`, accepts values such as `30s`, `5m`, `1h`, or raw milliseconds, and accepts `0` to disable idle shutdown. `relaunch: true` maps to `--relaunch`. `extraArgs` carries per-command options and display or emulation flags such as `--engine`; it cannot set `--config` or global flags that change network, file, policy, or host access. Set host-wide options in the MCP server's environment or selected config.

By default, tool invocations use the same config discovery and environment variables as the CLI. Use `session` in the tool arguments, or set `FROB_SESSION`, to isolate browser state.

Pass `--config <trusted-path>` to `frob mcp` or `frob mcp call` to select one trusted config file. MCP tool child processes load only that file, replacing default user/project discovery. Put any required safety policy in it. Environment variables and accepted per-tool CLI arguments keep their normal precedence.

## Command chaining

Chain commands with `&&` in a single shell invocation. The browser persists via a background daemon, so chaining works naturally and is more efficient than separate calls:

```bash
frob open example.com && frob wait --load domcontentloaded && frob snapshot -i
frob fill @e1 "user@example.com" && frob fill @e2 "pass" && frob click @e3
frob open example.com && frob wait --load load && frob screenshot page.png
```

Use `&&` when you don't need to read intermediate output. Run commands separately when you need to parse output first (e.g., snapshot to discover refs, then interact with those refs).
