The `snapshot` command returns a compact accessibility tree with refs for element interaction.

## Options

Filter output to reduce size:

Compact snapshots (`-c`) keep visible text, status text, and their direct ancestors. Empty sibling branches are removed. Interactive snapshots (`-i`) filter out noninteractive content. MCP snapshots default to interactive; set `interactive: false` to retain visible text and status text.

```bash
frob snapshot                    # Full accessibility tree
frob snapshot -i                 # Interactive elements only (recommended)
frob snapshot -c                 # Compact (remove empty elements)
frob snapshot -d 3               # Limit depth to 3 levels
frob snapshot -s "#main"         # Scope to CSS selector
frob snapshot -i -c -d 5         # Combine options
```

## Output format

Each line is an element: its role, its name in quotes, then attributes and the ref in brackets. A full snapshot of a small shop page:

```bash
frob snapshot
# - navigation
#   - link "Home" [ref=e1]
#   - link [ref=e2] hint="img:cart"
#     - image
# - main
#   - heading "Orders" [level=1, ref=e3]
#   - paragraph
#     - text "You have 2 open orders. See the"
#     - link "help page" [ref=e5]
#     - text "."
#   - table
#     - row
#       - columnheader "Order" [ref=e7]
#       - columnheader "Total" [ref=e8]
#     - row
#       - cell "Blue mug" [ref=e10]
#       - cell "$12" [ref=e11]
#       - cell [ref=e12] > button "Edit" [ref=e16]
#   - textbox "Email" [ref=e6]
#   - button "Subscribe" [ref=e4]
```

The same page with `-i`, which keeps only elements to act on, plus headings and landmarks:

```bash
frob snapshot -i
# - link "Home" [ref=e1]
# - link [ref=e2] hint="img:cart"
# - heading "Orders" [level=1, ref=e3]
# - link "help page" [ref=e5]
# - button "Edit" [ref=e16] hint="in:Blue mug $12"
# - button "Edit" [ref=e17] hint="in:Red plate $9"
# - textbox "Email" [ref=e6]
# - button "Subscribe" [ref=e4]
```

### What a snapshot leaves out

A snapshot prints what an agent needs and leaves out what repeats or carries no meaning:

- Wrappers with no role of their own (unnamed `generic` elements, layout tables, labels, and inline formatting such as `strong` or `code`) give way to their content.
- Text that the page splits across inline elements is joined into one `text` line. A paragraph reads as text lines between its links.
- A node whose only content is one run of text shows that text as its name, and a name that only repeats the node's content is printed once.
- `-i` leaves out table cells and list items. Their refs still exist, so `get text @e10` works, and a full snapshot shows them.

## Control hints

Controls whose accessible name is empty, or shared with another ref in the same snapshot, carry a hint read from the DOM after the ref. Refs themselves are unchanged:

```bash
frob snapshot -i
# - link [ref=e1] hint="img:cart"
# - button [ref=e2] hint="icon:icon-trash; in:Blue mug"
# - button [ref=e3] hint="icon:fa-heart; in:Blue mug"
# - button [ref=e4] hint="img:pencil; id:edit-btn; in:Blue mug"
# - textbox "Email" [ref=e5] hint="name:login-email"
# - textbox "Email" [ref=e6] hint="name:newsletter-email"
```

Parts are joined with `; ` in this order, and each appears only when it is found:

  <thead>
    <tr><th>Part</th><th>Source</th></tr>

  <tbody>
    <tr><td><code>icon:</code></td><td>SVG sprite id from <code>&lt;use href="#..."&gt;</code>, the <code>&lt;svg&gt;</code> <code>id</code> or <code>data-icon</code>, or an icon library class such as <code>lucide-trash</code> or <code>fa-heart</code></td></tr>
    <tr><td><code>img:</code></td><td>File name of an image inside the control, without the extension</td></tr>
    <tr><td><code>data-testid:</code>, <code>name:</code>, <code>id:</code></td><td>The first of those attributes set on the control whose value is made of words, such as <code>edit-btn</code>. Generated values such as <code>mwEek</code> are skipped</td></tr>
    <tr><td><code>in:</code></td><td>Text of the nearest table row, list item, or article around the control. Interactive snapshots (<code>-i</code>) only, since a full snapshot already prints that text</td></tr>
  </tbody>
</table>

Hints are on by default in every snapshot mode. In `--json` output the hint sits in the `snapshot` text and the `refs` map keeps its empty `name`. Iframe refs never get a hint.

A hint is not the accessible name. `find role <role> --name` and stale-ref recovery match on the name only, so act on these elements by ref. A control with no name and nothing to read still prints with no hint.

## Using refs

Refs from the snapshot map directly to commands:

```bash
frob click @e2      # Click the Submit button
frob fill @e3 "a@b.com"  # Fill the email input
frob get text @e1        # Get heading text
```

## Ref lifecycle

Surviving DOM elements retain their refs across snapshots and same-document updates. Replacing an element or navigating its page or iframe invalidates its refs without recycling IDs. Virtual accessibility nodes have snapshot-local refs. Re-snapshot after interactions to observe changes, and always after navigation:

```bash
frob click @e4      # Navigates to new page
frob snapshot -i    # Get fresh refs
frob click @e8      # Use a ref from the new snapshot
```

A ref keeps pointing at its DOM node while that node exists. If the node was replaced, frob falls back to the one element with the same role and name, but only when the ref was unique in its snapshot. When duplicates make the match ambiguous, the action fails without acting. Run `snapshot` again and use a fresh ref.

## Annotated screenshots

For visual context alongside text snapshots, use `screenshot --annotate` to overlay numbered labels on interactive elements. Each label `[N]` maps to ref `@eN`:

In native mode, annotated screenshots currently work on the CDP-backed browser path (Chromium/Lightpanda). The Safari/WebDriver backend does not yet support `--annotate`.

```bash
frob screenshot --annotate ./page.png
# -> Screenshot saved to ./page.png
#    [1] @e1 button "Submit"
#    [2] @e2 link "Home"
#    [3] @e3 textbox "Email"
frob click @e2
```

Headless Chromium screenshots hide native scrollbars for consistent image output. Pass `--hide-scrollbars false` when launching to keep native scrollbars visible.

Annotated screenshots also cache refs, so you can interact with elements immediately. This is useful when the text snapshot is insufficient for unlabeled icons, canvas content, or visual layout verification.

## Iframes

Presentational iframes use the same `Iframe` role for snapshots and stale-ref recovery.

Snapshots automatically detect and inline iframe content. Each `Iframe` node in the main frame is resolved and its child accessibility tree is included directly beneath it. Refs assigned to elements inside iframes carry frame context, so interactions work without switching frames first.

```bash
frob snapshot -i
# - heading "Checkout" [level=1, ref=e1]
# - Iframe "payment-frame" [ref=e2]
#   - textbox "Card number" [ref=e3]
#   - button "Pay" [ref=e4]

frob fill @e3 "4111111111111111"
frob click @e4
```

Only one level of iframe nesting is expanded. Cross-origin iframes that block accessibility tree access and empty iframes are silently omitted.

To scope a snapshot to a single iframe, switch into it first:

```bash
frob frame @e2
frob snapshot -i       # Only elements inside that iframe
frob frame main        # Return to main frame
```

## Best practices

1. Use `-i` to reduce output to actionable elements
2. Re-snapshot after page changes to get updated refs
3. Scope with `-s` for specific page sections
4. Use `-d` to limit depth on complex pages
5. Use `screenshot --annotate` when visual context is needed alongside refs

## JSON output

For programmatic parsing in scripts:

```bash
frob snapshot --json
# {"success":true,"data":{"snapshot":"...","refs":{"e1":{"role":"heading","name":"Title"},...}}}
```

Note: JSON uses more tokens than text output. The default text format is preferred for AI agents.
